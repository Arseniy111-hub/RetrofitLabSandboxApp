# Техническое задание: Retrofit Lab — Sandbox App

## 1. Цель проекта

Написать небольшое отдельное Android-приложение для ручной практики Retrofit. Без старого кода, без
старой навигации, без старых багов. Когда все заработает, ты сможешь перенести поиск картинок в свое
приложение заметок.

### Правила выполнения:

- **Ты пишешь весь код сам.**
- Проси у ментора **подсказки**, а не готовые решения.
- После каждого этапа отправляй код на ревью.

---

## 2. Технологический стек

- **Язык и UI:** Kotlin, Jetpack Compose, Material 3
- **Сеть:** Retrofit 2.11.0 + `converter-gson 2.11.0`
- **Логирование:** OkHttp `logging-interceptor 4.12.0`
- **Асинхронность и состояние:** Coroutines, StateFlow
- **Загрузка изображений:** Coil
- **Архитектура:** MVI (Intent, State, ViewModel) — как в `RoomDbPractice`
- **Навигация:** Navigation Compose (`NavHost`, `rememberNavController`) / `PrimaryTabRow`

### Правила настройки (выученные на ошибках зависимости Room):

1. Начинай с шаблона New Project в Android Studio.
2. Не меняй самостоятельно версии AGP, Kotlin и других основных библиотек.
3. Добавляй по одной зависимости за раз. Делай **Sync** и **Build** после каждой.
4. Добавь разрешение `INTERNET` в `AndroidManifest.xml`.
5. Не выкладывай API-ключи в GitHub. Опционально: храни ключ в `local.properties`.

## 3. Три вкладки приложения

| Вкладка     | API             | Base URL                                | Нужен ключ?     | Основные навыки                             |
|:------------|:----------------|:----------------------------------------|:----------------|:--------------------------------------------|
| **Posts**   | JSONPlaceholder | `https://jsonplaceholder.typicode.com/` | Нет             | `@GET`, `@Query`, `@Path`, `@POST`, `@Body` |
| **Images**  | Pixabay         | `https://pixabay.com/`                  | Да (бесплатный) | Поиск, класс-обертка, Interceptor           |
| **Weather** | Open-Meteo      | `https://api.open-meteo.com/`           | Нет             | Вложенный JSON, `@SerializedName`           |

> *Примечание:* Pexels не используется, так как они приостановили выдачу новых API-ключей.

### Вкладка 1: Posts (Посты)

1. Отобразить список постов с помощью `GET posts`.
2. Фильтрация по пользователю (userId от 1 до 10) с использованием `@Query`.
3. Нажатие на пост — просмотр деталей поста через `GET posts/{id}` с использованием `@Path`.
4. Создание поста: форма с заголовком (`title`) и телом (`body`), затем `POST posts` с `@Body`.
   Показать ответ сервера. Сервер только имитирует сохранение, поэтому новый пост не появится в
   общем списке.
5. *(Опционально)* Отображение комментариев к посту через `GET posts/{id}/comments`.

### Вкладка 2: Images (Картинки)

1. Поле ввода для поиска и кнопка «Искать» (без debounce на первых этапах).
2. Вызов поиска Pixabay (эндпоинт `api/` с параметрами `q` и `image_type=photo`). Ответ приходит в
   виде объекта-обертки, внутри которого лежит список картинок. Изучи документацию и возьми только
   нужные поля.
3. Отображение результатов в `LazyVerticalGrid` с использованием Coil.
4. Если поисковый запрос пустой — ничего не делать.
5. Отображение трех состояний: загрузка (loading), ошибка (error), пустой результат (empty).
6. Нажатие на картинку: открытие картинки в увеличенном размере и сохранение её URL в состоянии
   экрана. *(Это пригодится для приложения заметок).*
7. На Этапе 4 передавай ключ как `@Query` в функции API. На Этапе 5 перенеси добавление ключа в
   `Interceptor`.

### Вкладка 3: Weather (Погода)

1. Вызов `v1/forecast` с параметрами `latitude`, `longitude` и `current` (температура и скорость
   ветра). Уточнить точные названия параметров в документации Open-Meteo.
2. Добавить 3–4 кнопки городов с фиксированными координатами.
3. Ответ содержит вложенный объект и имена полей в `snake_case`. Используй `@SerializedName` и
   Kotlin-стиль именования (camelCase) в своих DTO-классах.
4. Отобразить температуру и скорость ветра.

## 4. Правила сетевого слоя (Network Layer)

- Используй сетевой объект с `by lazy`. Каждый `baseUrl` **должен заканчиваться на `/`**. У тебя три
  разных `baseUrl`: реши, как создавать экземпляры Retrofit, и объясни почему.
- **DTO-классы** (модели данных сервера) отделены от **UI State**. Используй только необходимые
  поля.
- Все API-функции должны быть `suspend`. Выбери один стиль: возвращать чистое тело ответа (`T`) или
  `Response<T>`. Используй его везде и объясни свой выбор.
- **Интерцепторы (Interceptors):**
    - Один для логирования (`HttpLoggingInterceptor`), чтобы видеть URL и JSON в Logcat.
    - Один кастомный Interceptor, добавляющий API-ключ Pixabay к каждому запросу этого API.
- Используй `sealed class` для сетевых результатов: `Loading`, `Success(data)`, `Error(message)`.
  ViewModel помещает результат в State.
- Обработай следующие случаи:
    - Отсутствие интернета (проверяй в режиме «В самолете»).
    - Ошибка сервера или неверный API-ключ (измени одну букву в ключе для проверки).
    - Пустой результат.
    - Некорректный/неожиданный JSON (анализируй Logcat).

---

## 5. Правила MVI

- Для каждой вкладки создается свой `Intent` (sealed interface), свой `State` (data class) и своя
  `ViewModel`.
- У ViewModel есть приватный `_state` и публичный `state`. Внутри ViewModel чтение происходит только
  через `_state.value`.
- `State` иммутабелен (неизменяем). Для обновления используй `.copy()`.
- UI считывает состояние через `collectAsState()` / `collectAsStateWithLifecycle()` и отправляет
  `Intent`. UI никогда не меняет состояние напрямую.

## 8. Вопросы для самопроверки

*Отвечай своими словами, не подглядывая в конспекты:*

1. Что делает метод `.create(Api::class.java)`?
2. Почему `baseUrl` обязан заканчиваться на `/`?
3. В каких случаях используются `@Path`, `@Query` и `@Body`?
4. Почему для Pixabay требуется класс-обертка, а для `GET posts` — нет?
5. Что происходит, если имя поля в JSON отличается от имени свойства в Kotlin? Как это исправить?
6. Почему использовать `Interceptor` лучше, чем добавлять API-ключ вручную в каждую функцию API?
7. В чем разница между отсутствием интернета и HTTP ошибкой 404? Как твое приложение отображает
   каждую из них?
8. Почему перехват `catch (e: Exception)` внутри корутины может стать проблемой (например, для
   `CancellationException`)?
